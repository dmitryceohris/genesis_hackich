# Как записать демо

**Команда:** Лесхан Уаис, Тухватуллина Дилайла, Оспан Салих

Инструкция для того, кто записывает видео, и ему не нужно знать проект
изнутри. Все команды копируются как есть.

## Сразу главное: интерфейса нет, и это не упущение

Продукт — не приложение для человека, а среда для дообучения модели. Её
пользователь — агент, а не оператор: он запрашивает записи пятью действиями и
сдаёт выводы, и никакого экрана ему не нужно. Кнопок в задании нет ни в
требованиях, ни в критериях оценки.

Поэтому демо терминальное, и говорить о нём нужно именно так: «вот среда, вот
её контракт, вот агент внутри неё, вот почему её награде можно верить». Если
начать извиняться за отсутствие интерфейса, смотрящий решит, что чего-то не
хватает. Не хватает только того, чего не просили.

## Подготовка

Нужен Python 3.11 или новее. Больше ничего: ни установки зависимостей, ни
сети, ни докера.

```powershell
git clone https://github.com/dmitryceohris/genesis_hackich.git
```

```powershell
cd genesis_hackich
```

Проверка, что всё на месте (должно напечатать `186 passed`):

```powershell
python -m pytest tests -q
```

Если `pytest` не установлен — это не проблема, обязательный прогон от него не
зависит:

```powershell
python -m unittest discover -s tests -t .
```

## Запись: одна команда

```powershell
python scripts/demo.py --pause
```

Сценарий из семи шагов. Флаг `--pause` останавливается перед каждым шагом и
ждёт Enter — это и нужно для записи с голосом: нажимаете Enter, когда
договорили. Без флага всё пробегает подряд, годится для быстрого прогона.

Другой эпизод — `--seed 7`. Каждый seed даёт другую компанию, другие суммы и
другие дефекты, но ту же структуру, так что сценарий не изменится.

### Что говорить на каждом шаге

**Шаг 1, данные.** Генератор строит книги с нуля: 51 счёт, около 60 платежей,
270 проводок двойной записи, 1460 ежедневных курсов — и затем вносит дефекты
четырёх типов. Стоит отдельно сказать: все денежные суммы целые в минимальных
единицах, курсы — десятичные строки. Ни одного числа с плавающей точкой в
деньгах, потому что `0.1 + 0.2` в них не равно `0.3`.

**Шаг 2, контракт.** Агент не получает книги целиком — только пять действий,
каждое стоит шаг, бюджет 100. Покажите, что ответ всегда имеет три поля, а
ошибка приходит кодом из закрытого списка: `unknown_table`, и ни путей, ни
seed, ни таймингов, по которым можно было бы угадать ответ.

**Шаг 3, агент.** Базовая политика сверки восстанавливает бухгалтерские
тождества и сдаёт четыре вывода, каждый с доказательствами — ID записей,
которые подтверждают расхождение. Обратите внимание на суммы: политика их
вычисляет, а не угадывает.

**Шаг 4, оценка.** Вывод верен, только если совпали тип, затронутые записи,
сумма и валюта — и доказательства достаточны. Сопоставление взаимно
однозначное, через максимальное паросочетание: жадный проход занижал бы
результат, когда один вывод подходит к двум ошибкам эталона.

**Шаг 5, это главный шаг.** Здесь ответ на единственный вопрос, который
по-настоящему задают такой среде: что она даёт за правильный ответ без
обоснования. Берём эталонную заявку, где всё верно, и выбрасываем
доказательства:

```
эталонная заявка    TP=4 FP=0 FN=0, награда +1.000
без доказательств   TP=0 FP=4 FN=4, награда -1.000
с выдуманным ID     TP=3 FP=1 FN=1, награда +0.500
структура сломана   валидна=False,  награда -1.000
```

Скажите вслух: правильный ответ без обоснования аудиторским выводом не
является, и среда это понимает. Выдуманный ID доказательства не проходит,
потому что проверяется не только достаточность набора, но и достижимость
каждого ID инструментами агента. Сломанная структура уходит в −1 отдельным
путём, а не через F1 = 0, — это разные события, и журнал оценщика их
различает.

**Шаг 6, независимая проверка.** Валидатор получает только публичный снимок:
доступа к эталону у него нет по сигнатуре функции, а не по договорённости. Он
держит бухгалтерские равенства, заново выводит каждое расхождение и ищет
расхождения, о которых эталон молчит. Стоит сказать, что эта проверка нашла
два настоящих дефекта в наших же данных — недостижимое доказательство и
неполный набор для ошибки распределения, — и оба описаны в `DESIGN.md`.

**Шаг 7, базовые линии.** Если формула награды верна, стратегии обязаны
разойтись. Честная сверка получает +0.920, «пометить всё» — −1.000 с 30
ложными обвинениями, случайный поиск тратит 40 шагов впустую. Награда
различает поведение, а не шум.

## Если нужно показать больше

Обязательная проверка, шесть шагов, ни один не прерывает остальные:

```powershell
python scripts/verify_all.py
```

Наборы эпизодов на диск — 10 обучающих и 10 отложенных, каждый каталогом из
восьми файлов, плюс индекс с сидами и настройками:

```powershell
python scripts/build_episode_sets.py
```

Официальные определения проверок, воспроизведённые тестами — двадцать тестов
блока 3 и открытые примеры M01–M12 с их же числами:

```powershell
python -m pytest tests/test_official_checks.py -v
```

Контейнеры (нужен запущенный Docker; на машине разработки он не поднялся,
подробности в `README.md`):

```powershell
python scripts/check_images.py
```

## Что честно сказать про незавершённое

Лучше назвать самому, чем оставить судье на находку. Три вещи:

- сборка образов не выполнялась: Docker Desktop установлен, но движку нужен
  компонент Windows `VirtualMachinePlatform`, то есть полная перезагрузка,
  которую перед сдачей делать не стали;
- базовый образ закреплён тегом, а не digest — следствие того же;
- прогон под Python 3.11 не проводился, локально был только 3.14; минимальная
  версия проверяется первым шагом обязательного прогона.

Всё это уже записано в `README.md` и `DESIGN.md` с причинами — не как
оправдание, а как список того, что проверено, и того, что нет.

## Если что-то не запустилось

**Кракозябры вместо русского текста.** Консоль Windows не в UTF-8:

```powershell
python -X utf8 scripts/demo.py --pause
```

**`ModuleNotFoundError`.** Команда запущена не из корня репозитория. Проверьте
`Get-Location`: должно заканчиваться на `genesis_hackich`.

**`python` не найден, но есть `py`.** Подставьте `py -3` вместо `python`.
