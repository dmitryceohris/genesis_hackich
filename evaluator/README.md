## Независимая проверка эталона

`validator/` получает только публичный снимок и политику и отвечает на четыре
вопроса критерия «Данные и эталон»:

1. держатся ли бухгалтерские равенства — баланс по `journal_id`, сумма позиций
   против `total_minor`, уникальность публичных ID, целостность ссылок,
   покрытие фиксингами, отсутствие закрытых полей в выгрузке;
2. выводится ли каждое объявленное расхождение из публичных записей;
3. нет ли расхождений, о которых эталон молчит — по критериям противоречивые
   данные не считаются сложностью, а просто теряют баллы;
4. достижим и достаточен ли каждый объявленный набор доказательств.

```powershell
python scripts/verify_episodes.py
```

Скрипт пишет `artifacts/verification.json` и возвращает ненулевой код, если
хотя бы один эпизод не прошёл, — он рассчитан на вызов из `make verify`.

Независимость обеспечена структурно: `reconstruct` принимает снимок и не
получает `truth`, а арифметика продублирована в `validator/arithmetic.py`
вторым маршрутом — точные дроби и ручное полуцелое округление вместо
`Decimal`. Тест `ArithmeticAgreementTests` сверяет обе реализации на сетке
курсов и сумм. Честная граница: валидатор и политика сверки читают одни и те же
опубликованные правила, поэтому предметную модель стоит отдать на вычитку
третьему человеку — автоматика здесь не заменяет ревью.

Что проверка уже нашла в наших же данных: `POLICY-PERIOD` в наборе
доказательств был недостижим через `get_record`, а набор для ошибки
распределения не содержал записи курса, без которой сумму 1250 не вывести. Оба
случая закреплены регрессионными тестами и описаны в разделе 9a контракта.

## Как пользоваться оценщиком

```python
from evaluator import score

report = score(submission, truth, inspection_steps, truncated=False)
report.reward, report.tp, report.fp, report.fn, report.f1
```

`score` чистая: повторный вызов на тех же входах даёт тот же отчёт, поэтому
повторная отправка заявки не может изменить оценку.

Oracle вызывается только доверенной стороной:

```python
from evaluator import build_oracle_submission

score(build_oracle_submission(truth), truth, 0).reward  # 1.0
```

## Что нужно от зоны генератора

1. `truth.json` в виде из раздела 2 контракта. Критично: поле
   `acceptable_evidence_sets` — **список наборов**, каждый достаточен целиком.
   Набор не может быть пустым: `build_oracle_submission` на таком эталоне
   падает намеренно, потому что ошибку нельзя подтвердить.
2. Публичные записи с полями из докстринга `tests/fixtures.py`. Политике сверки
   нужны именно:
   - `role` на строке журнала (`expense`, `liability`, `allocation`,
     `suspense`, `cash`) — проверки опираются на роль, а не на имя счёта;
   - `source_minor` и `source_currency` на строках платежа, иначе FX-ошибку
     нельзя пересчитать из публичных данных;
   - `line_items[].service_date` и `line_items[].obligation_id`, иначе не
     проверяются период и дубль;
   - `invoice_refs[].share_minor` в документе платежа, иначе не проверяется
     распределение.
3. Соглашение: FX-ошибка объявляется один раз и ключуется платежом и строкой
   денежного счёта, а не каждой переоценённой строкой. Иначе на одном платеже
   появляются три разных FX-находки, и эталон становится неоднозначным.
4. Каждый эпизод должен проходить `tests/test_policies.py` в части решаемости:
   `reconcile` обязан давать F1 = 1. Если не даёт — эталон требует
   недоступного факта, и это дефект данных.

## Зона среды: что уже выполнено

Всё перечисленное ниже реализовано в `environment/` и закреплено тестами в
`tests/test_environment.py`:

1. пять действий из раздела 04 задания и ограниченные коды ошибок;
2. авторитетный счётчик `inspection_steps`, который передаётся оценщику;
   оценщик его не пересчитывает, шаг `submit` в счётчик не входит;
3. усечение: 100-е исследовательское действие и исчерпанный предел времени
   дают один и тот же итог — пустая заявка и `truncated=true`, отличимый от
   невалидного `submit`;
4. в закрытом режиме числовая награда интерфейса всегда 0, включая последний
   шаг.

Контейнер изоляции агента написан: `Dockerfile.agent` и `runner/`, команда
запуска со всеми флагами в `README.md`. В образ не копируются `generator/`,
`validator/` и `evaluator/oracle.py`, поэтому эталон недостижим физически.
Фактическая сборка образа не выполнялась: Docker Desktop установлен, но его
движок требует компонента Windows `VirtualMachinePlatform`, то есть полной
перезагрузки системы, и перед сдачей её решили не делать. Проверка обоих
образов одной командой: `python scripts/check_images.py`.

## Известные границы

- `reconcile` — простой алгоритм сверки, а не сильный аудитор. Его задача —
  доказать решаемость эпизода и достижимость доказательств, а не показать
  высокий балл.
- Проверка на утечку устроена как канарейка в приватных полях
  (`tests/test_policies.py::LeakageTests`). Полную проверку изоляции процесса,
  сети и файлов делает владелец среды: из этого пакета её не видно.
- Фикстуры маленькие. Лимит в 30 выводов на них не достигается, поэтому он
  проверяется на синтетическом наборе записей.
- При усечении на чистой книге пустая заявка даёт положительный возврат. Это
  следствие общей формулы задания; эффект закреплён тестом и должен попасть в
  записку о дизайне.
